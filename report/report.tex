\section{Experimental Protocol}
The objective is to separate optimization effects from regularization
effects while holding the architecture and data pipeline fixed. We use
torchvision's \texttt{efficientnet\_v2\_s} with
\texttt{weights=None} and a 120-way output layer
\citep{tan2021efficientnetv2}. The default SiLU activations are retained;
the assignment does not prescribe a separate activation-function ablation.
All experiments use cross-entropy and SGD with momentum $m=0.9$.
Each condition starts from a fresh random initialization with seed 42;
later conditions do not continue training an earlier model. Checkpoints
support recovery within a condition without changing the total epoch budget.
The single-seed design does not establish statistical significance.

The learning-rate stage consists of three 15-epoch runs. The schedule,
weight-decay, and mixup stages consist of five 300-epoch runs, giving
$3\times15+5\times300=1545$ training epochs in total. The initial rate
for the long runs minimizes the final training loss in the first stage,
as specified in the assignment. For other configuration choices we maximize
final validation accuracy, breaking ties by lower validation cross-entropy.
The best pre-mixup 300-epoch configuration is the control for mixup.
The final model is selected among all five long runs using this same
validation rule. This rule is fixed before inspecting test performance.
Final-epoch metrics are reported rather than metrics at a selectively
chosen epoch; the test uses the selected model's final checkpoint.

\section{Data Preprocessing}
The required split sizes are 7,155 training, 1,533 validation, and 1,534
test images, totaling 10,222. Supplied splits are preserved. The code
checks split sizes, label membership, repeated paths, and audits byte-identical
images across splits. Supplied split membership is retained even when duplicate
bytes are found; the measured overlap is disclosed rather than silently removing
images. Conflicting labels for identical bytes are retained as supplied and
quantified as annotation inconsistency. If only the original unsplit labelled images are
available, an explicitly requested seeded stratified split produces these
exact counts; its provenance is recorded and must be disclosed. Kaggle's
unlabelled competition test set is not the assignment's labelled hold-out set.

RGB images are resized using bilinear interpolation to $100\times100$.
For each channel $c$, over the $N=7155\times100\times100$ resized training
pixels scaled into $[0,1]$, we compute
\begin{equation}
 \mu_c=\frac{1}{N}\sum_{i=1}^{N}x_{ic},\qquad
 \sigma_c=\sqrt{\frac{1}{N}\sum_{i=1}^{N}(x_{ic}-\mu_c)^2}.
\end{equation}
The normalized input is $z_{ic}=(x_{ic}-\mu_c)/\sigma_c$.
This is channel-wise standardization, not full covariance whitening.
Validation and test images never contribute to these statistics.

Training augmentation is applied before normalization, so zero padding
means black image pixels rather than zeros in normalized coordinates.
The implemented training transform is:
\begin{lstlisting}[language=Python]
T.Compose([
    T.Resize((100, 100), antialias=True),
    T.RandomHorizontalFlip(p=0.5),
    T.RandomCrop(100, padding=12,
        padding_mode="constant", fill=0),
    T.ToTensor(),
    T.Normalize(mean, std),
])
\end{lstlisting}
Validation and test use only resize, tensor conversion, and normalization.
For comparable curves, after each training epoch we also evaluate the
unaugmented training set with the model in evaluation mode. Thus the plotted
training and validation CE/top-1 metrics use the same input and model-mode
conventions. Augmented optimization loss and accuracy are logged separately.
All epoch averages are weighted by the number of samples, including the
last incomplete batch. The reported CE excludes the weight penalty.

\section{Learning Rate Schedule}
Cosine annealing reduces the rate smoothly, first slowly, then more rapidly,
and finally slowly as it approaches zero. Without warm restarts, its rule is
\begin{equation}
 \eta_t=\frac{\eta_0}{2}\left(1+\cos\frac{\pi t}{T}\right),
 \quad T=300,\quad 0\leq t\leq T.
\end{equation}
Here $t$ is the number of completed epochs. Epoch 1 uses $\eta_0$, the
scheduler steps after each epoch, and its stored rate reaches zero at the
boundary after epoch 300. This is the no-restart version of cosine annealing
associated with SGDR \citep{loshchilov2017sgdr}. The normalized schedule in
Figure~\ref{fig:cosine} is a mathematical illustration, not a training result.

Decaying the rate can permit finer late-stage optimization when a constant
rate keeps updates noisy. A schedule can also reduce exploration too early;
therefore an improvement is not guaranteed. Evidence should include final
training CE, validation CE, and the late-epoch trajectories. A lower
training CE without improved validation performance would indicate an
optimization gain without a corresponding measured generalization gain.

\section{Weight Decay}
The two prescribed coefficients are $\lambda=5\times10^{-4}$ and
$10^{-4}$, with cosine annealing and the selected initial learning rate.
Both runs last 300 epochs. The zero-decay cosine run is reused as the control.
For the implemented PyTorch SGD, the update is
\begin{align}
 g_t &= \nabla_w L(w_t)+\lambda w_t,\\
 v_t &= 0.9v_{t-1}+g_t,\qquad w_{t+1}=w_t-\eta_t v_t.
\end{align}
The penalty is applied to all model parameters, including biases and
normalization parameters, consistently across both conditions. Under this
coupled SGD implementation, adding $\lambda\|w\|_2^2/2$ to the objective
is equivalent to adding $\lambda w$ to the gradient. Decoupled weight decay
and this coupled penalty are different with momentum or adaptive
optimizers; this experiment uses the assignment's SGD setting, not AdamW.

training--validation accuracy gap alone does not prove improvement: it
can also arise when training performance deteriorates. The relevant
evidence is whether validation accuracy or CE improves, together with
the corresponding training curves.

\section{Mixup and Final Evaluation}
For a random within-batch pairing $(i,j)$, mixup constructs
\begin{align}
 \lambda &\sim \operatorname{Beta}(0.2,0.2),\\
 \widetilde{x} &= \lambda x_i+(1-\lambda)x_j,\\
 \widetilde{y} &= \lambda y_i+(1-\lambda)y_j.
\end{align}
The loss is $\lambda\operatorname{CE}(f(\widetilde{x}),y_i)
+(1-\lambda)\operatorname{CE}(f(\widetilde{x}),y_j)$
\citep{zhang2018mixup}. We draw one coefficient per batch and permute
examples within the batch. Mixing occurs after cropping, flipping, and
standardization. For fixed channel statistics, standardization is affine
and therefore commutes with this convex mixing operation.

The beta probability density is
\begin{equation}
 p(\lambda)=\frac{\lambda^{-0.8}(1-\lambda)^{-0.8}}{B(0.2,0.2)},
 \quad 0<\lambda<1.
\end{equation}
It is symmetric and U-shaped, with integrable singularities at both
endpoints. Consequently many mixtures are close to one constituent,
although intermediate mixtures remain possible. Figure~\ref{fig:beta}
plots the density on a log vertical axis without evaluating the endpoints.
